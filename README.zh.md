# Backup Guard 扩展 — 备份守卫

> 在副作用操作（write/edit/危险 bash 命令）前自动备份文件。

## 概述

Backup Guard 是一个 Pi 扩展，实现"先备份，后执行"的安全策略。在执行任何有副作用的操作之前，将受影响的文件复制到备份目录，让你可以从操作失误中恢复。

### 覆盖范围

| 工具 | 行为 |
|------|------|
| **write** | 覆盖前备份目标文件（新建文件自动跳过） |
| **edit**  | 修改前备份目标文件 |
| **bash**  | 检测危险命令（`rm`、`rmdir`、`del`、`rd`、`truncate`、`mv`、`Remove-Item`、`Move-Item` 等），备份涉及的文件 |

## 备份目录结构

借鉴 `.history` 风格：

```
<项目>/backups/<相对路径>/<基名>_<时间戳>.<扩展名>   ← 文件快照（修改/删除统一）
<项目>/backups/<相对路径>/<时间戳>/                  ← 目录快照（rm -rf 整树）
```

删除与修改统一为"操作前快照"，恢复时只需复制回原路径即可。操作上下文可通过 Pi 会话历史追溯。

## 使用方式

### 自动备份

Backup Guard 在使用 `write`、`edit` 或 `bash` 工具时自动运行，无需手动配置。

- **备份成功** → 显示通知 → 放行原操作
- **目标文件不存在** → 跳过（如 `write` 新建文件）→ 放行原操作
- **目标位于 `backups/` 内** → 跳过（防止递归复制自身）→ 放行原操作
- **目标位于工作目录外** → 跳过 → 放行原操作
- **备份失败（权限/磁盘问题）** → 阻止原操作

### 查看备份

在 Pi 中运行 `/backups` 命令，查看最近 10 条备份记录。

### 清理备份

手动删除 `backups/` 下不需要的目录或文件即可。

## 配置说明

默认备份目录为当前工作目录下的 `backups/`。只处理工作目录内的文件。

> **提示：** 如果项目是 git 仓库，建议将 `backups/` 加入 `.gitignore`。

## 配置参考

| 设置项 | 默认值 | 说明 |
|--------|--------|------|
| `BACKUP_DIR_NAME` | `"backups"` | 备份根目录名 |
| `BLOCK_ON_BACKUP_FAILURE` | `true` | 备份失败时是否阻止原操作 |

## 安装

### 前置条件

- Pi Coding Agent
- Node.js 18+

### 安装步骤

```bash
# 克隆扩展到 Pi agent 扩展目录
git clone <仓库地址> agent/extensions/backup-guard

# 或手动复制目录
cp -r backup-guard agent/extensions/backup-guard
```

将扩展放置在 `agent/extensions/` 下后，Pi 会自动加载。

## 工作原理

1. **拦截**：Pi 在调用 `write`、`edit` 或 `bash` 时触发 `tool_call` 事件。
2. **分析**：对于 `bash`，扩展解析命令，从危险命令段中提取路径 token。
3. **备份**：每个候选路径以时间戳命名备份（同一次操作的所有路径共享同一时间戳——"一起备份"）。
4. **决策**：备份成功则放行原操作；备份失败则阻止原操作（可配置）。

## 命令

| 命令 | 说明 |
|------|------|
| `/backups` | 查看最近 10 条备份记录 |

## 安全机制

- **防递归复制**：`backups/` 内的文件不会被再次备份。
- **工作目录守卫**：只处理当前工作目录下的文件。
- **权限感知**：权限错误会阻止操作，防止数据丢失。
- **时间戳隔离**：每次备份使用唯一时间戳（含随机后缀），防止并发冲突。
